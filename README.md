# Nexus · ใยเซลล์

เว็บรวบรวมชนิดเซลล์ในร่างกายมนุษย์ ที่เชื่อมข้อมูลเป็นใยเครือข่ายตาม Cell Ontology (CL)
ผู้ใช้หลักคือนักเรียนที่เตรียมสอบ กสพท และผู้สนใจชีววิทยาเซลล์ เนื้อหาสองภาษา (ไทย/อังกฤษ)
เว็บเป็น static site บน GitHub Pages ใช้ Cytoscape.js

**สถานะ:** ขั้นที่ 1–5 เสร็จแล้ว (ข้อมูลครบ 11 ระบบ 265 รายการ (เซลล์ 250 ชนิด หมวด 15 หมวด) ใยรายระบบ ใยภาพรวม หน้าเนื้อเยื่อ โหมดทดสอบ เปรียบเทียบเซลล์ สลับภาษาไทย/อังกฤษ ใช้งานออฟไลน์ และหน้าเกี่ยวกับ)

## โครงสร้างโฟลเดอร์

```
data/systems.json         ระบบอวัยวะ 11 ระบบ
data/tissues.json         เนื้อเยื่อหลัก 4 ประเภท + หมวด other
data/cells/<system>.json  ข้อมูลเซลล์ หนึ่งไฟล์ต่อระบบ (เขียนเอง)
data/checklist.json       รายการตรวจเซลล์ที่ควรมี จัดกลุ่มตามระบบ (ใช้กับคำสั่ง coverage)
data/edges/<system>.json  เส้นใยที่คัดเอง หนึ่งไฟล์ต่อระบบ
data/generated/           ไฟล์ที่สคริปต์สร้าง (cl_terms.json; cache/ อยู่ใน .gitignore)
reports/                  รายงานจากสคริปต์
scripts/nexus.py          เครื่องมือหลัก (validate / fetch / build / images)
scripts/layout.mjs        คำนวณตำแหน่งใยภาพรวมล่วงหน้า (Node.js)
package.json              แพ็กเกจของ Node (ระบุเวอร์ชันแน่นอน) ใช้กับ layout.mjs เท่านั้น
site/                     หน้าเว็บ (โฟลเดอร์นี้คือสิ่งที่ deploy)
  index.html
  css/style.css
  js/                     main, router, views, overview, tissue, card, graph, ui, data, util ... (ES modules)
  data/nexus.json         ข้อมูลรวมสำหรับหน้าเว็บ (สร้างจาก build ห้ามแก้เอง)
  data/layout-overview.json  ตำแหน่งของใยภาพรวม (สร้างจาก build ต้อง commit ไปด้วย)
  images/<slug>/          รูปของเซลล์ (หลายรูปได้) ส่วนเนื้อเยื่อใช้ images/tissues/<id>/
  images/_originals/      ต้นฉบับก่อนย่อรูป (ไม่ขึ้น GitHub)
```

ต้องใช้ Python 3 เท่านั้น ไม่ต้องติดตั้งไลบรารีเพิ่ม (ยกเว้นคำสั่ง `images --optimize` ที่ต้องมี Pillow)

## วิธีใช้สคริปต์

```bash
python scripts/nexus.py validate          # ตรวจข้อมูล
python scripts/nexus.py fetch             # ดึงข้อมูลจาก OLS4 (Cell Ontology)
python scripts/nexus.py build             # รวมเป็น site/data/nexus.json
python scripts/nexus.py images            # ตรวจไฟล์รูป และพิมพ์ JSON ตั้งต้นของรูปใหม่
python scripts/nexus.py coverage          # เทียบข้อมูลกับ data/checklist.json
```

| คำสั่ง | ทำอะไร |
|---|---|
| `validate` | ตรวจรูปแบบ CL ID, id/slug ซ้ำ, kind, ชื่อ en/th, ระบบและเนื้อเยื่อที่อ้างถึงมีอยู่จริง, confused_with และปลายเส้นทุกเส้น, เส้นที่ชี้หาตัวเอง, ช่อง `images` ของทุกรูป (ช่องบังคับ ประเภท ไฟล์มีจริง src ไม่ซ้ำ รูปลิงก์ภายนอกต้องมี source และแจ้งข้อผิดพลาดถ้ายังเหลือช่อง `image` แบบเก่า) แบ่งเป็น **ข้อผิดพลาด** (exit code 1) กับ **คำเตือน** (ช่องว่าง ยังไม่มีรูป หนึ่งบรรทัดต่อเซลล์) |
| `fetch` | ดึง label, definition, synonyms, สถานะ obsolete, is_a ancestors และ develops_from ของทุก CL ID เก็บ cache รายเซลล์ แล้วรวมเป็น `data/generated/cl_terms.json` และเขียน `reports/fetch-report.md` |
| `images` | หาไฟล์ใน `site/images/` ที่ยังไม่อยู่ในข้อมูลแล้วพิมพ์ JSON ตั้งต้นให้คัดลอก แจ้งรูปที่มีในข้อมูลแต่ไม่มีไฟล์ และไฟล์ที่ใหญ่เกิน 500 KB หรือกว้างเกิน 1600 px `--optimize` ย่อรูปและแปลงเป็น WebP (ต้องติดตั้ง Pillow: `python -m pip install Pillow` ถ้าไม่มีสคริปต์แค่แจ้งแล้วทำส่วนอื่นต่อ) เก็บต้นฉบับไว้ที่ `site/images/_originals/` และแก้ `src` ในข้อมูลให้ตามอัตโนมัติ |
| `coverage` | เทียบ `data/checklist.json` กับข้อมูลจริง จับคู่ด้วย CL ID ก่อน ถ้ารายการยังไม่มี `id` จับคู่ด้วยชื่อ `en` กับ `en`, `cl.label` และ `synonyms` (ไม่สนตัวพิมพ์) เขียน `reports/coverage.md` (สรุปเซลล์/หมวดแยกตามระบบ, ยังขาด, มีแล้ว, และเซลล์ในข้อมูลที่ไม่อยู่ในรายการตรวจ ซึ่งไม่ใช่ข้อผิดพลาด) และ `reports/missing-cl.md` (รายการที่หารหัส CL ไม่เจอ) |
| `build` | รัน validate ก่อน (ถ้ามีข้อผิดพลาดจะไม่สร้างไฟล์) แล้วรวมข้อมูลทั้งหมดเป็น `site/data/nexus.json` และเขียน `reports/build-report.md` เทียบเส้นใยที่คัดเองกับ CL จากนั้นเรียก `scripts/layout.mjs` ต่อท้ายอัตโนมัติถ้าเครื่องมี Node.js (ไม่มีก็แจ้งเตือนแล้วทำต่อ) |

ตัวเลือกของ `fetch`:

- `--refresh` ดึงใหม่แม้มี cache
- `--only CL:0000235,CL:0000576` ดึงเฉพาะรหัสที่ระบุ
- `--sleep 0.2` หน่วงเวลาระหว่างคำขอ (วินาที)

## ข้อมูลเซลล์ (`data/cells/<system>.json`)

ไฟล์เป็นรายการ (array) ของเซลล์และหมวด ใช้ CL ID เป็นตัวหลัก
**ไม่ต้องเก็บคำนิยามและ synonyms ภาษาอังกฤษ** สคริปต์ดึงจาก CL ให้เอง

ช่องที่ช่องว่างได้ ให้เว้นว่าง (`""` หรือ `[]`) ห้ามเดา การ์ดบนเว็บจะซ่อนหัวข้อที่ว่าง

### เซลล์ (`"kind": "cell"`)

| ช่อง | ความหมาย |
|---|---|
| `id` | CL ID เช่น `CL:0000775` (7 หลัก) |
| `slug` | ชื่อสั้น kebab-case ใช้เป็นชื่อไฟล์รูปและ URL เช่น `neutrophil` |
| `kind` | `"cell"` |
| `en`, `th` | ชื่ออังกฤษ (ตรงกับ label หรือ synonym ใน CL) และชื่อไทย |
| `systems` | รายการ id ระบบ เซลล์ที่อยู่หลายระบบใส่หลายค่า **ค่าแรก (`systems[0]`) คือระบบหลัก** ใช้เป็นตำแหน่งของเซลล์ในใยภาพรวมแบบจัดกลุ่มตามระบบ (ดูหัวข้อ "ระบบหลัก") |
| `tissue`, `tissue_subtype` | id เนื้อเยื่อหลักและชนิดย่อยจาก `tissues.json` ถ้าไม่ระบุ `tissue` validate จะเตือน และเซลล์จะไปอยู่กลุ่ม `other` ในใยภาพรวมแบบตามเนื้อเยื่อ |
| `location` | ตำแหน่งที่พบ |
| `morphology` | ลักษณะรูปร่างและโครงสร้าง |
| `function` | หน้าที่ |
| `secretes` | สารที่เซลล์หลั่ง (ว่างได้ถ้าไม่หลั่งสารเด่น) |
| `markers` | marker บนผิวเซลล์หรือในเซลล์ |
| `lifespan` | อายุเซลล์ |
| `exam` | จุดออกสอบและข้อควรจำ |
| `diseases` | โรคหรือภาวะที่เกี่ยวข้อง |
| `confused_with` | CL ID ของเซลล์ที่มักสับสน (ต้องอยู่ในชุดข้อมูล) |
| `en_content` | (ไม่บังคับ) เนื้อหาภาษาอังกฤษ `{location, morphology, function, exam}` ช่องไหนไม่มีจะแสดงเนื้อหาไทยพร้อมป้าย "Thai only" ในโหมดอังกฤษ (ดูหัวข้อ "สลับภาษา") |
| `images` | รายการรูป (`[]` ถ้ายังไม่มี) รูปแรกคือรูปหลัก ดูหัวข้อ "วิธีใส่รูป" |
| `verified` | `true` เมื่อตรวจเนื้อหาไทยกับตำราแล้ว (เริ่มต้น `false`) |
| `refs` | ตำราหรือแหล่งอ้างอิงที่ใช้ตรวจ |

### หมวด (`"kind": "class"`)

ใช้แค่ `id`, `slug`, `kind`, `en`, `th`, `systems`, `tissue`, `tissue_subtype`, `function`, `images`, `verified`, `refs`
หมวดคือกลุ่มกว้างของเซลล์ เช่น leukocyte, lymphocyte ไม่ใช่เซลล์ชนิดเดียว

### ผลที่สคริปต์เติมให้ใน `nexus.json`

- `purl` ลิงก์ถาวรของเทอมใน CL
- `cl` ประกอบด้วย `label`, `definition`, `synonyms`, `obsolete` (ได้ค่ามาจาก `fetch`)

## ระบบหลัก (primary system)

เซลล์ที่อยู่หลายระบบต้องเรียง `systems` ให้ **ระบบหลักอยู่ลำดับแรก** ระบบหลักคือระบบที่เซลล์ทำหน้าที่หรืออยู่เป็นหลัก เช่น

| เซลล์ | systems | เหตุผล |
|---|---|---|
| Kupffer cell | `["digestive", "blood-immune"]` | แมโครฟาจประจำตับ |
| alveolar macrophage | `["respiratory", "blood-immune"]` | แมโครฟาจประจำถุงลม |
| microglial cell | `["nervous", "blood-immune"]` | เกลียประจำระบบประสาทส่วนกลาง |
| osteoclast | `["skeletal", "blood-immune"]` | ทำงานที่ผิวกระดูก |
| enteroendocrine cell | `["digestive", "endocrine"]` | อยู่ในเยื่อบุทางเดินอาหาร |

ระบบหลักมีผลเฉพาะตำแหน่งในใยภาพรวมแบบตามระบบ ส่วนใยรายระบบยังแสดงเซลล์ทุกตัวที่มีระบบนั้นอยู่ใน `systems`

## ระบบและเนื้อเยื่อ

`systems.json`: แต่ละระบบมี `id`, `th`, `en`, `color` (`#RRGGBB`), `summary`, `organs`

`tissues.json`: แต่ละประเภทมี `id`, `th`, `en`, `color`, `cl_class`, `features`, `location`, `function`, `exam` (จุดออกสอบของเนื้อเยื่อ แสดงเป็นกล่องเด่นในหน้าเนื้อเยื่อ ว่างได้), `germ_layers`, `images`, `subtypes`
หมวด `other` ไม่มี `cl_class` สำหรับเซลล์ที่ไม่เข้าสี่ประเภท (เซลล์สืบพันธุ์ สเต็มเซลล์)

เลือดจัดเป็นเนื้อเยื่อเกี่ยวพัน เซลล์สายเลือดจึงใช้ `tissue: "connective"` กับ subtype `blood`, `hematopoietic` หรือ `lymphoid` ตามตำแหน่ง

## เส้นใย (`data/edges/<system>.json`)

```json
{
  "develops_from": [["CL:ลูก", "CL:แม่"]],
  "is_a": [["CL:ลูก", "CL:แม่"]],
  "interacts_with": [{ "from": "CL:...", "to": "CL:...", "th": "คำอธิบายสั้น ๆ", "mode": "hormone" }]
}
```

- `develops_from` และ `is_a` เขียนเป็นคู่ **[ลูก, แม่]** เสมอ
- `interacts_with` ไม่มีใน CL ต้องเพิ่มเอง ทิศทางจาก `from` ไปยัง `to`
- `mode` ของ `interacts_with` **จำเป็น** (validate จะแจ้งข้อผิดพลาดถ้าขาด) ค่าได้ 5 แบบ แต่ละแบบมีสีและลายเส้นต่างกันบนเว็บ

| mode | ความหมาย | ตัวอย่าง |
|---|---|---|
| `hormone` | ฮอร์โมนผ่านกระแสเลือด | beta cell → hepatocyte (insulin) |
| `synapse` | สัญญาณผ่านไซแนปส์ | rod cell → bipolar cell |
| `paracrine` | สารสื่อสารระยะใกล้ | delta cell → beta cell (somatostatin) |
| `support` | เซลล์สนับสนุนเซลล์อื่น | oligodendrocyte → pyramidal neuron (ไมอีลิน) |
| `immune` | ปฏิสัมพันธ์ของระบบภูมิคุ้มกัน | dendritic cell → helper T cell |

- เส้น `interacts_with` ข้ามระบบได้ ในใยรายระบบ เซลล์ปลายทางที่อยู่นอกระบบจะแสดงเป็นจุดจางสีของระบบนั้น (ghost node) แตะแล้วไปหน้าเซลล์นั้น
- เส้นที่ปลายทางอยู่ในระบบที่ยังไม่ได้เพิ่ม ให้รอจนกว่าจะเพิ่มระบบนั้น (ตอนนี้ครบทั้ง 11 ระบบแล้ว)
- ทุกเส้นใน `nexus.json` มี `source: "curated"` (คัดเอง)
- ใน `nexus.json` ใช้ `from`/`to` เหมือนกันทุกชนิดเส้น โดย `develops_from` และ `is_a` มี `from` เป็นลูก `to` เป็นแม่

`build-report.md` เทียบเส้น `is_a` และ `develops_from` ที่คัดเองกับ CL ให้ ใช้ตัดสินว่าจะแก้เส้นใดเอง
(CL ระบุ `develops_from` ของเซลล์เม็ดเลือดไว้น้อย เส้นที่ "คัดเองแต่ CL ไม่มี" จึงมีมาก ไม่ได้แปลว่าผิดเสมอไป)

## วิธีใส่รูป

เซลล์และเนื้อเยื่อมีรูปได้หลายรูป เช่น ภาพกล้องจุลทรรศน์แสง ภาพกล้องอิเล็กตรอน และภาพวาดแผนผังของเซลล์เดียวกัน
**ใช้เฉพาะรูปที่ได้รับอนุญาตให้ใช้เท่านั้น ห้ามใช้รูปจาก Google ทั่วไปหรือรูปที่ไม่ทราบสัญญาอนุญาต**
การมีลิงก์ไม่ได้ทำให้พ้นเรื่องลิขสิทธิ์ ต้องตรวจสัญญาอนุญาตทุกรูป

แหล่งรูปที่ใช้ได้:

- [Wikimedia Commons](https://commons.wikimedia.org/) ดูสัญญาอนุญาตของแต่ละไฟล์ (CC BY, CC BY-SA, CC0, public domain)
- [Human Protein Atlas](https://www.proteinatlas.org/) ตามเงื่อนไขการใช้ของเว็บนั้น (ภาพเนื้อเยื่อ CC BY-SA 4.0)
- รูปที่ถ่ายเองจากกล้องจุลทรรศน์ในแลปหรือที่โรงเรียน (ใส่ชื่อผู้ถ่ายเป็น `credit`)

### รูปแบบข้อมูล

ช่อง `images` เป็นรายการ **รูปแรกคือรูปหลัก** ใช้ในการ์ดย่อและหน้าเปรียบเทียบ

```json
"images": [
  {
    "src": "images/neutrophil/blood-smear.webp",
    "type": "micrograph",
    "alt_th": "นิวโทรฟิลในสไลด์เลือด นิวเคลียสหลายพู",
    "caption_th": "สไลด์เลือดย้อม Wright-Giemsa กำลังขยาย 1000 เท่า",
    "caption_en": "",
    "stain": "Wright-Giemsa",
    "magnification": "1000x",
    "credit": "ชื่อผู้ถ่าย",
    "license": "CC BY-SA 4.0",
    "source": "https://commons.wikimedia.org/wiki/File:..."
  }
]
```

| ช่อง | |
|---|---|
| `src` **บังคับ** | พาธนับจาก `site/` ต้องไม่ซ้ำกันทั้งเว็บ ถ้าเป็นลิงก์ `http(s)://` ต้องมี `source` ด้วย (แต่ควรเก็บไฟล์ไว้ในเว็บ เพราะลิงก์ภายนอกเสี่ยงเสียและใช้ออฟไลน์ไม่ได้) |
| `type` **บังคับ** | ดูตารางด้านล่าง |
| `alt_th` **บังคับ** | คำบรรยายรูปสำหรับโปรแกรมอ่านหน้าจอ (โหมดอังกฤษใช้ชื่อเซลล์แทน) |
| `credit`, `license` **บังคับ** | ผู้สร้างรูปและสัญญาอนุญาต แสดงใต้รูปและในหน้า "เกี่ยวกับ" (จัดกลุ่มตามสัญญาอนุญาต) |
| `caption_th`, `caption_en` | คำอธิบายใต้รูป (ถ้าไม่มี `caption_en` โหมดอังกฤษจะแสดง `caption_th` พร้อมป้าย Thai only) |
| `stain`, `magnification`, `source` | วิธีย้อม กำลังขยาย (เช่น `1000x`) และหน้าต้นทางของรูป |
| `quiz` | `false` = ไม่ใช้รูปนี้ในโหมดทดสอบ (ดูด้านล่าง) |

ค่า `type`:

| type | ความหมาย |
|---|---|
| `micrograph` | ภาพจากกล้องจุลทรรศน์แสง |
| `em` | ภาพจากกล้องจุลทรรศน์อิเล็กตรอน (TEM, SEM) |
| `photo` | ภาพถ่ายทั่วไป เช่น ตัวอย่างเนื้อเยื่อ |
| `illustration` | ภาพวาด |
| `diagram` | แผนผัง |

### โครงสร้างโฟลเดอร์

```text
site/images/<slug>/<ชื่อไฟล์>            รูปของเซลล์ เช่น images/neutrophil/blood-smear.webp
site/images/tissues/<id>/<ชื่อไฟล์>      รูปของเนื้อเยื่อ เช่น images/tissues/connective/loose.webp
site/images/_originals/...               ต้นฉบับก่อนย่อ (อยู่ใน .gitignore ไม่ขึ้น GitHub และไม่ถูก deploy)
```

### ขั้นตอนเพิ่มรูป

1. วางไฟล์ในโฟลเดอร์ของเซลล์ (สร้างโฟลเดอร์ตาม `slug` ถ้ายังไม่มี) ควรเป็น WebP/JPEG กว้างไม่เกิน 1600 px และไม่เกิน 500 KB
2. รัน `python scripts/nexus.py images` จะได้ JSON ตั้งต้นของไฟล์ใหม่ (เติม `src`, `type` ที่เดาจากชื่อไฟล์ และ `alt_th` ให้แล้ว) และคำเตือนถ้าไฟล์ใหญ่เกิน
   (ถ้าไฟล์ใหญ่ รัน `python scripts/nexus.py images --optimize` ก่อน)
3. คัดลอก JSON ไปวางในช่อง `images` ของเซลล์หรือเนื้อเยื่อนั้น ตรวจ `type`
4. เติม `credit` และ `license` (กับ `source`, `caption_th`, `stain`, `magnification` ถ้ามี)
5. รัน `python scripts/nexus.py validate` แล้ว `build`

### การแสดงผลในเว็บ

- หน้าเซลล์และหน้าเนื้อเยื่อ: รูปใหญ่หนึ่งรูป แถบรูปย่อด้านล่าง (ไม่แสดงถ้ามีรูปเดียว) ตัวกรองตามประเภท (แสดงเมื่อมีมากกว่าหนึ่งประเภท) caption ประเภท วิธีย้อม กำลังขยาย และเครดิตของรูปที่ดูอยู่ มือถือปัดซ้ายขวา คอมพิวเตอร์ใช้ปุ่มลูกศร กดรูปเพื่อดูเต็มจอ ซูมด้วยล้อเมาส์ ปุ่ม +/− หรือบีบนิ้ว ปิดด้วย Esc
- ไม่มีรูป: แสดงกรอบ "ยังไม่มีรูป" พร้อมบอกโฟลเดอร์ที่ควรใส่ รูปที่โหลดไม่สำเร็จแสดงกรอบ "โหลดรูปไม่สำเร็จ" เฉพาะรูปนั้น
- การ์ดย่อในใยและหน้าเปรียบเทียบใช้รูปแรก หน้าเปรียบเทียบเลือกเทียบตามประเภทรูปได้
- โหมดทดสอบ (ข้อ "จากรูปภาพ"): สุ่มจากทุกรูปของเซลล์ **ข้ามรูป `diagram` และ `illustration`** เพราะมักมีชื่อเซลล์เขียนในภาพ ถ้ารูปนั้นไม่มีชื่อในภาพและอยากใช้ ให้ใส่ `"quiz": true` ถ้ารูปประเภทอื่นไม่เหมาะ ใส่ `"quiz": false`
- ออฟไลน์: รูปที่เคยเปิดแล้วถูกเก็บไว้ใช้ต่อ (service worker เก็บทุกพาธใต้ `images/`)

เว็บเป็นไฟล์ static ไม่มี build step แต่ต้องเปิดผ่านเซิร์ฟเวอร์ (เปิดไฟล์ตรง ๆ จะโหลด `nexus.json` ไม่ได้) และต้องต่ออินเทอร์เน็ตเพื่อโหลดไลบรารีกราฟและฟอนต์จาก CDN

แล้วเปิด http://localhost:8000/ หน้าเว็บอ่านข้อมูลจาก `site/data/nexus.json` เท่านั้น
เมื่อเพิ่มระบบใหม่ในข้อมูลแล้วรัน `build` การ์ดระบบบนหน้าแรกและใยรายระบบจะขึ้นเองโดยไม่ต้องแก้โค้ด

## สลับภาษาไทย/อังกฤษ

- ข้อความทั้งหมดของหน้าเว็บ (เมนู ปุ่ม หัวข้อ ข้อความแจ้งเตือน) อยู่ใน `site/i18n/th.json` และ `en.json` **ไม่มีข้อความในโค้ด** ใช้ `t('คีย์', {พารามิเตอร์})` จาก `js/i18n.js` ข้อความที่มี `{n}` จะถูกแทนค่า
- เพิ่มข้อความใหม่ต้องใส่ทั้งสองไฟล์ ตรวจด้วย `node scripts/test-i18n.mjs` (ไม่มีอักษรไทยในไฟล์ .js ไม่นับคอมเมนต์, คีย์ที่ใช้มีครบ, สองไฟล์มีคีย์เท่ากันและพารามิเตอร์ตรงกัน)
- ภาษาเริ่มต้นตามเบราว์เซอร์ (ขึ้นต้นด้วย `th` เป็นไทย นอกนั้นอังกฤษ) จำที่เลือกไว้ใน `localStorage` (`nexus.lang`) และตั้ง `lang` ของ `<html>` ให้ตรง
- **โหมดอังกฤษ:** ชื่อเซลล์ ระบบ และเนื้อเยื่อเป็นอังกฤษ คำนิยามจาก Cell Ontology เป็นเนื้อหาหลัก
- **เนื้อหาภาษาอังกฤษของข้อมูล (ไม่บังคับ):**
  - เซลล์: `en_content: {location, morphology, function, exam}` (ช่องใดช่องหนึ่งก็ได้)
  - ระบบ: `en_summary` (ข้อความเดียว) เนื้อเยื่อ: `en_content: {features, location, function, exam}`
  - ถ้าไม่มี จะแสดงเนื้อหาไทยพร้อมป้าย "Thai only" รายการ (`secretes`, `markers`, `diseases`) ที่มีอักษรไทยก็ติดป้ายเดียวกัน
  - validate ตรวจชนิดของช่องเหล่านี้และสรุปว่ามีกี่เซลล์ที่มี `en_content` (ตอนนี้ครบเฉพาะระบบเลือดและภูมิคุ้มกัน)
- โหมดทดสอบใช้ได้ทั้งสองภาษา ภาษาอังกฤษถามเฉพาะข้อที่มีข้อมูลอังกฤษ (เช่น ข้อ "จากลักษณะ" ต้องมี `en_content.morphology`)

## โหมดทดสอบ (`#/quiz`)

สร้างคำถามปรนัย 4 ตัวเลือกจากข้อมูลอัตโนมัติ เพิ่มเซลล์หรือระบบใหม่แล้วใช้ได้ทันที โค้ดสร้างคำถามอยู่ใน `site/js/quiz-engine.js` (ไม่แตะ DOM)

| ประเภท | ถามอะไร | ใช้ช่องข้อมูล |
|---|---|---|
| `morphology` | ลักษณะนี้เป็นเซลล์ใด | `morphology` |
| `secretes` | เซลล์ใดหลั่งสารนี้ | `secretes` |
| `marker` | เซลล์ใดมี marker นี้ | `markers` |
| `develops_from` | เซลล์นี้เจริญมาจากเซลล์ใด | เส้น `develops_from` |
| `tissue` | เซลล์นี้อยู่ในเนื้อเยื่อชนิดใด | `tissue` |
| `interacts` | เซลล์นี้ส่งสัญญาณ (ตาม mode) ไปยัง/มาจากเซลล์ใด | เส้น `interacts_with` |
| `image` | รูปนี้เป็นเซลล์ใด | `image` (เฉพาะเซลล์ที่มีรูปที่ใช้ในโหมดทดสอบได้ ดูหัวข้อ "วิธีใส่รูป") |

- ไม่สร้างคำถามจากช่องที่ว่าง
- **ตัวเลือกผิดต้องผิดจริง:** ตัวเลือกผิดต้องไม่เอ่ยถึงคำใบ้ในข้อมูลของตัวเอง ไม่เกี่ยวข้องกันทาง `is_a` กับคำตอบ ไม่ใช่ต้นกำเนิดของเซลล์ในคำถาม (ข้อ develops_from) และไม่เคยมีปฏิสัมพันธ์กับเซลล์นั้น (ข้อ interacts) ถ้าหาตัวเลือกผิดไม่ครบ 3 ตัวจะข้ามคำถามนั้น
  ตัวเลือกหลอกเลือกจากเซลล์ใน `confused_with` ก่อน แล้วชนิดย่อย/ระบบ/เนื้อเยื่อเดียวกัน
- คำถามจากเซลล์ที่ `verified: false` มีป้าย "ข้อมูลยังไม่ได้ตรวจ" ตัวเลือก "ใช้เฉพาะข้อมูลที่ตรวจแล้ว" ใช้ไม่ได้จนกว่าจะมีเซลล์ที่ตรวจแล้วพอ
- ใช้แป้นพิมพ์ได้: 1–4 เลือก Enter ยืนยัน และ Enter อีกครั้งไปข้อถัดไป
- เก็บเซลล์ที่เคยตอบผิดใน `localStorage` (คีย์ `nexus.quiz.wrong`) ใช้ให้น้ำหนักตอนสุ่มและฝึกเฉพาะเซลล์ที่เคยผิด
- ลิงก์ล็อกขอบเขต: `#/quiz?system=digestive`, `#/quiz?tissue=epithelial`, `#/quiz?cell=CL_0000091`

ทดสอบตัวสร้างคำถาม (สร้าง 1,000 ข้อจากข้อมูลจริงทั้งภาษาไทยและอังกฤษ และตรวจว่าถูกข้อเดียว ไม่ซ้ำ ไม่ว่าง และตัวเลือกผิดไม่ตรงกับคำใบ้):

```bash
node scripts/test-quiz.mjs
```

- `site/404.html` ใช้กับ GitHub Pages: ข้อความสองภาษา แล้วพากลับหน้าแรกอัตโนมัติ (ใน GitHub Pages แบบโปรเจกต์ใช้ชื่อ repo จาก path เป็นฐาน)

## ใช้งานออฟไลน์ (PWA)

- `site/manifest.json` + ไอคอนใน `site/icons/` (ออกแบบเป็น SVG แล้วแปลงเป็น PNG ด้วย `npm run icons` เมื่อแก้ SVG เท่านั้น ผลลัพธ์ commit ไว้แล้ว) ติดตั้งเป็นแอปบนมือถือ/คอมพิวเตอร์ได้
- `site/sw.js` (service worker, ลงทะเบียนเฉพาะ https หรือ localhost):
  - ตอนติดตั้งเก็บไฟล์ทั้งหมดใน `site/precache.json` (ให้ `build` สร้างอัตโนมัติ ไม่ต้องแก้มือ) และไลบรารีจาก CDN
  - ไฟล์เว็บ (html, js, css, i18n) ลองเครือข่ายก่อน ถ้าไม่มีเน็ตใช้ที่เก็บไว้ จึงได้โค้ดใหม่เสมอเมื่อออนไลน์
  - ข้อมูล (`nexus.json`, `layout-overview.json`) รูป ฟอนต์ และไลบรารี CDN ใช้ที่เก็บไว้ก่อน
- **เวอร์ชันข้อมูล:** `build` คำนวณ hash ของเนื้อหาใน `nexus.json` (ไม่รวมเวลาสร้าง) ใส่ใน `meta.data_version` และ `site/data/version.json` เว็บตรวจ `version.json` ทุกครั้งที่เปิด ถ้าต่างจากที่โหลดอยู่ จะแสดงแถบ "มีข้อมูลใหม่ กดเพื่ออัปเดต" กดแล้ว service worker ดึงข้อมูลใหม่ลงที่เก็บและโหลดหน้าใหม่
- ต้อง commit `site/precache.json` และ `site/data/version.json` ที่ `build` สร้างไว้ด้วย
- ทดสอบด้วย Chrome/Edge จริงแบบ headless: เปิดเว็บ ปิดเซิร์ฟเวอร์ โหลดใหม่ เปิดทุกหน้า สลับภาษา ทำโหมดทดสอบ และตรวจแถบอัปเดต

node scripts/test-offline.mjs      # ตั้ง CHROME_PATH ถ้า Chrome/Edge อยู่ที่อื่น

(เบราว์เซอร์ในแอป Claude ไม่รองรับ service worker จึงใช้สคริปต์นี้ทดสอบแทน)

## ใยภาพรวมและตำแหน่งที่คำนวณไว้ล่วงหน้า

ใยภาพรวมมีเซลล์จำนวนมาก การคำนวณ layout ในเบราว์เซอร์ทุกครั้งช้าและทำให้ภาพไม่เหมือนเดิม จึงคำนวณตำแหน่งไว้ล่วงหน้าด้วย Node.js
2 แบบ (ตามระบบ และตามเนื้อเยื่อ) แล้วเก็บใน `site/data/layout-overview.json`

**ความต้องการ:** Node.js 18 ขึ้นไป (ทดสอบกับ v24) ใช้เฉพาะตอน build ไม่ต้องใช้ตอนเปิดเว็บ

```bash
npm install                      # ครั้งแรกครั้งเดียว (ติดตั้ง cytoscape และ fcose เวอร์ชันที่ระบุไว้ใน package.json)
python scripts/nexus.py build    # สร้าง nexus.json แล้วเรียก layout ต่อให้อัตโนมัติ
node scripts/layout.mjs          # หรือรันเฉพาะ layout (อ่าน nexus.json ที่มีอยู่)
```

- ผลลัพธ์เหมือนเดิมทุกไบต์เมื่อข้อมูลไม่เปลี่ยน (ตำแหน่งเริ่มต้นกำหนดได้ + ตัวสุ่มมีเมล็ด)
  ถ้า fcose แบบ `randomize: false` ให้ผลเสียรูป (ยุบเป็นเส้นทแยง ซึ่งเกิดกับการจัดกลุ่มตามเนื้อเยื่อ) สคริปต์จะคืนตำแหน่งเริ่มต้นแล้วรันแบบ `randomize: true` ด้วยตัวสุ่มมีเมล็ดแทน ซึ่งยังเหมือนเดิมทุกครั้ง
- ไฟล์เก็บแฮชของรายการจุด (พร้อมระบบหลักและเนื้อเยื่อของแต่ละจุด) และรายการเส้น หน้าเว็บตรวจแฮชนี้ ถ้าไฟล์ไม่มีหรือไม่ตรงกับข้อมูล
  เว็บจะคำนวณในเบราว์เซอร์แทน (ช้ากว่า) และเตือนใน console
- ถ้าไม่มี Node: `build` จะแจ้งเตือนและข้ามขั้นนี้ เว็บยังใช้ได้ แต่ต้อง commit `layout-overview.json` ที่เพิ่งสร้างจากเครื่องที่มี Node ไว้ก่อน deploy เพื่อให้เปิดเร็ว
- ต้อง **commit `site/data/layout-overview.json`** ทุกครั้งที่ข้อมูลเปลี่ยน (`node_modules/` ไม่ต้อง commit)

**การจัดกลุ่ม:** ตามระบบใช้ระบบหลัก (`systems[0]`) ของเซลล์ ตามเนื้อเยื่อใช้ `tissue` (ไม่มี `tissue` ไปกลุ่ม `other`)
**ซูมสองระดับ:** ซูมออกเห็นเฉพาะกลุ่มและเส้นรวมระหว่างกลุ่ม (ความหนาตามจำนวนเส้น) ซูมเข้าเห็นชื่อเซลล์และเส้นจริง

## Deploy บน GitHub Pages

`site/data/nexus.json` ถูกสร้างจาก `build` และต้อง commit ไปด้วย (GitHub Pages ไม่รัน Python ให้) มีสองวิธี:

**วิธี 1: GitHub Actions (แนะนำ เพราะรองรับโฟลเดอร์ `site/`)**
1. ไปที่ Settings → Pages → Source เลือก **GitHub Actions**
2. สร้างไฟล์ `.github/workflows/pages.yml`:

```yaml
name: Deploy site
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: site
      - id: deployment
        uses: actions/deploy-pages@v4
```

**วิธี 2: เลือกโฟลเดอร์โดยตรง** GitHub Pages เลือกโฟลเดอร์ได้เฉพาะ `/ (root)` หรือ `/docs` ดังนั้นถ้าไม่ใช้ Actions ให้ย้ายหรือคัดลอกเนื้อหาใน `site/` ไปไว้ที่ `docs/`

เว็บใช้ path แบบ relative และ routing ด้วย hash จึงทำงานได้ทั้งที่ `https://<user>.github.io/<repo>/` และโดเมนของตัวเอง

## รายการตรวจ (checklist) และคำสั่ง coverage

`data/checklist.json` คือรายการเซลล์ที่โปรเจกต์ตั้งใจให้ครอบคลุม จัดกลุ่มตามระบบ (`groups.<system>`; กลุ่ม `other` ใช้กับเซลล์ที่ไม่ใช่ระบบใดโดยเฉพาะ) แต่ละรายการมีช่อง:

| ช่อง | |
|---|---|
| `en` | ชื่อภาษาอังกฤษที่ใช้ค้นใน CL |
| `th` | ชื่อไทย (ถ้ารู้) |
| `id` | (ไม่บังคับ) CL ID ถ้าใส่ จะจับคู่ด้วย ID เท่านั้น ใส่เมื่อชื่อใน CL ต่างจาก `en` |
| `no_cl` | (ไม่บังคับ) `true` เมื่อหารหัส CL ไม่เจอ รายการนี้จะไม่ถูกนับว่าขาด และไปอยู่ใน `reports/missing-cl.md` |
| `nearest_parent` | (ใช้คู่กับ `no_cl`) CL ID ของคลาสแม่ที่ใกล้ที่สุด |
| `note` | หมายเหตุ |

เพิ่มรายการใหม่: เติมวัตถุ `{"en": "...", "th": "..."}` ในกลุ่มของระบบนั้น แล้วรัน `python scripts/nexus.py coverage` รายการที่ขึ้นว่า "ยังขาด" ให้ค้นรหัสด้วย OLS (https://www.ebi.ac.uk/ols4) ถ้าเจอก็เพิ่มเซลล์ตามขั้นตอนด้านล่าง ถ้าไม่เจอให้ใส่ `no_cl`, `nearest_parent` และ `note` ห้ามสร้างรหัสเอง

## วิธีเพิ่มระบบใหม่ (ไม่ต้องแก้โค้ด)

1. ตรวจว่า id ระบบมีอยู่ใน `data/systems.json` แล้ว (มีครบ 11 ระบบ)
2. สร้าง `data/cells/<system>.json` ตามรูปแบบด้านบน ใส่ `systems` ให้ถูก
   เซลล์ที่มีอยู่แล้วในอีกระบบ ไม่ต้องสร้างซ้ำ ให้เพิ่มระบบใน `systems` ของเซลล์เดิม
3. สร้าง `data/edges/<system>.json` (ไม่มีเส้นก็ใส่ `{}` ได้)
4. รัน `validate` แล้วแก้ข้อผิดพลาด
5. รัน `fetch` ตรวจ `reports/fetch-report.md` ว่ารหัสถูกต้อง ชื่อตรง และไม่ถูกยกเลิก
6. รัน `build` ตรวจ `reports/build-report.md` แล้วค่อยตัดสินใจเรื่องเส้นใย
7. (อัตโนมัติ) `build` คำนวณตำแหน่งใยภาพรวมใหม่ ถ้าเครื่องมี Node.js ให้ commit `site/data/layout-overview.json` ที่เปลี่ยนไปด้วย
8. ตรวจเนื้อหาไทยกับตำรา (Junqueira's Basic Histology, Campbell Biology) ก่อนตั้ง `verified: true`

ระบบที่เพิ่มแล้วจะปรากฏเองในหน้าแรก ใยรายระบบ ใยภาพรวม ตารางการเชื่อมข้ามระบบ และหน้าเนื้อเยื่อ โดยไม่ต้องแก้ไฟล์ใน `site/js/` เซลล์ที่อยู่หลายระบบให้เรียง `systems` โดยใส่ระบบหลักเป็นลำดับแรก
